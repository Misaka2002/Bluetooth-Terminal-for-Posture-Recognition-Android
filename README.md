# 姿态观察台 · Android

这是姿态观察台的安卓版本。手机接收 HC-06 发送的姿态分类结果，显示 3D 人物示意，并记录一次会话中每种姿态保持了多久。它使用与 [Windows 版本](https://github.com/Misaka2002/Bluetooth-Terminal-for-Posture-Recognition) 相同的八类姿态协议。

[查看完整演示界面](docs/images/android-demo.png)。截图由 Android 原生图形测试环境生成，使用模拟数据。

## 在手机上使用

应用支持 Android 8.0 及以上版本。安装 APK 后，可以先点击“演示模式”查看界面；演示不需要蓝牙设备，也不会混入真实设备的记录。当前界面为中文。

连接设备前，请在手机的系统蓝牙设置中配对 HC-06，然后回到应用，刷新已配对设备列表，选择设备并连接。Android 12 及以上需要允许“附近的设备”权限。应用只连接已经配对的经典蓝牙设备，不进行扫描，也不请求定位权限。HC-06 使用经典蓝牙 SPP，并不属于 BLE 设备。

连接期间，应用通过前台服务接收数据，通知栏会显示正在记录的提示，可以从通知直接断开连接。应用使用部分唤醒锁维持接收线程；断开连接时会释放。如果手机厂商限制后台应用，仍需在手机上实际验证熄屏后的持续接收。“演示模式”主要用于前台体验，不保证后台持续运行。

手机不需要设置串口波特率，HC-06 与 STM32 之间的 UART 配置仍需一致，沿用项目中已验证的 9600、8N1。

## 界面与统计

界面包含当前姿态、连续维持时间、正坐占比、切换次数、未识别时间，以及八种姿态各自的累计时长、最长连续时长和出现段数。3D 图集内置于 APK，运行时不会联网下载素材。

“显示原始终端”可展开接收日志，再次点击即可收起。它只改变日志区域的高度，手机界面宽度保持不变。屏幕最多保留最近 200 行，完整接收日志另外保存在本机；“清屏”不会删除日志文件或重置统计。

“新统计会话”先保存当前记录，再从零开始计时。如果蓝牙仍在连接中，会继续接收；跨会话的旧半行会被丢弃。进入和退出演示都会建立独立会话。

## 设备发送的数据

设备应发送以 LF 或 CRLF 结束的完整文本行：

```text
POSTURE=upright
POSTURE=forward_lean
```

| 姿态名称 | 中文显示 |
| --- | --- |
| `upright` | 正坐 |
| `forward_lean` | 前倾 |
| `backward_lean` | 后仰 |
| `left_lean` | 左倾 |
| `right_lean` | 右倾 |
| `forward_hunch` | 前弯含胸 |
| `left_hunch` | 左弯含胸 |
| `right_hunch` | 右弯含胸 |

左右方向以人物自身为准。程序也接受 `LABEL=<名称>` 和单独的姿态名称，大小写不敏感。只有数字 `ID` 的消息不参与统计；同一行出现多个分类字段时也会拒绝计入。超过 1024 字符的整行会被丢弃，下一行恢复接收。

计时从安卓终端创建会话时开始，以单调时钟记录完整行的到达时刻。同类姿态重复上报维持为一段；另一种姿态开始时，上一段结束。主动断开立即结束当前姿态。超过 2 秒没有新的有效分类时，后续时间记为未识别，不继续归入最后一个姿态。占比以有效姿态总时长为分母；出现次数只统计有正持续时长的段。

设备协议不包含 MCU 启动时间，所以手机无法补回连接前的姿态记录。计时精度还会受到设备发送周期与无线延迟影响。

## 保存和导出

每个会话保存在应用私有目录中，统计每 30 秒保存一次，也会在切换会话、断开、离开界面和服务正常结束时保存。进程被强制结束时，尚未保存的统计可能丢失；重新启动建立新会话，不把停机期间算成已有姿态。

“导出记录”生成当前会话的 ZIP，可通过系统文件选择器保存，也可以分享给其他应用。“历史记录”可以导出以前的会话。ZIP 内有：

| 文件 | 内容 |
| --- | --- |
| `summary.csv` | 每类姿态的时长、占比、最长连续时长、段数 |
| `timeline.csv` | 每段姿态的起止时刻与持续时长 |
| `session.json` | 会话来源、总时长、有效帧数等信息 |
| `received.log` | 带时间戳的完整接收日志 |

CSV 使用带 BOM 的 UTF-8，方便 Excel 打开中文。所有记录保存在本机，应用没有网络权限。只有主动保存或分享时，选中的导出文件才会交给其他应用。卸载应用会删除其私有会话，重要记录请先导出。

## 构建与测试

用 Android Studio 打开项目，安装 Android SDK 35 和 Build Tools 35.0.0，使用 JDK 17 或 21。项目包含 Gradle 8.11.1 Wrapper 和 Android Gradle Plugin 8.9.2。初次构建需要下载构建依赖。

Windows：

```powershell
.\gradlew.bat :core:test :app:testDebugUnitTest :app:assembleDebug :app:lintDebug
```

macOS / Linux：

```sh
./gradlew :core:test :app:testDebugUnitTest :app:assembleDebug :app:lintDebug
```

调试 APK 位于 `app/build/outputs/apk/debug/app-debug.apk`，用于安装测试。正式发布前应使用自己保管的签名密钥；密钥、本机 SDK 路径和生成 APK 都不提交到源码仓库。

`core/` 是不依赖 Android 的 Java 计时核心，单元测试覆盖解析、分片接收、超时、断开、迟到事件、时间守恒和报告一致性。`app/` 包含蓝牙接收服务、手机界面、本地保存和分享。蓝牙功能需在真实手机与 HC-06 上验证，模拟数据通过不代表硬件链路通过。

3D 图集复用 Windows 版本的生成素材；对应关系见 [素材说明](docs/assets.md)。
